# Грамматика Vibe

Спецификация первого этапа практикума. Требования [SPEC](../SPEC.md) и обозначения [API](../API.md) применяются к классической и агентной частям. Транслятор следующего этапа разбирает исходник `.vibe` вручную рекурсивным спуском и в дальнейшем генерирует C++20.

## 1. Обозначения (G-1)

В угловых скобках записаны нетерминалы. `::=` вводит правило, `|` разделяет варианты, `[ X ]` означает необязательную часть, `{ X }` — ноль или более повторений, круглые скобки без кавычек группируют части правила. Знаки и слова в кавычках должны присутствовать в исходнике. Имена прописными буквами без кавычек обозначают категории лексем. Стартовое правило — `<Program>`.

## 2. Лексика (G-2, LEX-1…LEX-10)

Исходник в UTF-8. Регистр значим. Лексема содержит вид, исходный текст и диапазон позиции. Строка и столбец считаются с единицы в символах, смещение — с нуля в байтах. Пробел, табуляция, CR и LF вне литералов пропускаются. CRLF считается одним переводом строки.

| Вид по API | Запись |
|---|---|
| `Keyword` | Зарезервированные слова из списка ниже |
| `Identifier` | `ID`: латинская буква или `_`, затем латинские буквы, цифры или `_`. Максимальный идентификатор сверяется с бором ключевых слов |
| `Literal` | `INT`, `DOUBLE`, `CHAR`, `STRING`, `UNIT` и фрагменты промпта. `true` и `false` лексер отдаёт как `Keyword`, парсер строит литеральный узел |
| `Operator` | `+`, `-`, `*`, `/`, `%`, `++`, `--`, `=`, `==`, `!=`, `<`, `<=`, `>`, `>=`, `&&`, `\|\|`, `!`, `,`. Запятая сохраняет вид `Operator` и в списках |
| `Delimiter` | `(`, `)`, `[`, `]`, `{`, `}`, `;`, `:`, `.` |
| `Unknown` | Недопустимый символ или неверный фрагмент. Лексер выдаёт диагностическое сообщение и продолжает до конца файла |
| `EndOfFile` | Единственная служебная лексема `EOF` в конце |

Ключевые слова определены списком:

```text
import func struct enum void int double bool char string list map future
if else while do for break continue goto return true false
model agent task on context use hide attempt ensure spawn await ask
tools budget space system worktree
```

`main`, `readInt`, `readDouble`, `readBool`, `readChar` и `readLine`, `print` — обычные идентификаторы.

- `INT` состоит из одной или нескольких цифр `0…9`. `DOUBLE` содержит десятичную часть между цифрами или экспоненту `e` либо `E` с необязательным знаком и одной или несколькими цифрами. Примеры — `0`, `12.5`, `12e-3`, `12.5E+3`. Знак перед числом — отдельный оператор.
- `UNIT` — число по правилу `INT` или `DOUBLE` и слитный суффикс `usd`, `tok`, `ktok`, `s` или `min`. Оно синтаксически допустимо в бюджете. Внутри `Literal` вид `Unit` уточняет число с единицей.
- `CHAR` записывается в одинарных кавычках и после декодирования содержит ровно один символ Unicode. `STRING` записывается в двойных кавычках и может быть пустой. В обоих допустимы `\n`, `\r`, `\t`, `\\` и экранирование соответствующей кавычки. Физический перевод строки внутри этих литералов запрещён.
- `//` пропускает комментарий до конца строки или файла. `/* … */` пропускает невложенный многострочный комментарий. Незакрытые литерал или комментарий дают `Unknown`.
- Лексер выбирает длиннейшую подходящую лексему. `a+++b` даёт `a`, `++`, `+`, `b`. `>>` не образует отдельной лексемы, поэтому `list<list<int>>` закрывается двумя `>`. После цифр соседняя буквенно-цифровая часть без допустимого суффикса, незавершённая экспонента и вторая точка с цифрой в том же числе дают ошибочный числовой фрагмент, например `35k6` и `3.5.7`. Точка без следующей цифры остаётся разделителем.
- Промпт заключён в обратные кавычки. В тексте экранируются обратная кавычка, обратная косая черта и начало подстановки `${`. Подстановка `${ ... }` переключает лексер на обычные лексемы. Стек режимов и счётчик фигурных скобок в каждой подстановке позволяют различать вложенные блоки и вложенные промпты. `PROMPT_FULL` включает обе обратные кавычки, `PROMPT_HEAD` — от открывающей кавычки до первого `${` включительно, `PROMPT_MID` — от закрывающей `}` до следующего `${` включительно, `PROMPT_TAIL` — от последней закрывающей `}` до обратной кавычки включительно. Все четыре формы имеют `LiteralKind::Prompt`, их роль определяется границами `lexeme`. Незакрытый промпт или подстановка дают лексическую ошибку.

## 3. Программа, типы и функции (G-3, К-1, К-2, К-7)

```ebnf
<Program>     ::= { <Import> } <ProgramItems>
<ProgramItems>::= <Definition> <ProgramItems>
                | <Declaration> <ProgramItems>
                | EOF
<Import>      ::= "import" <QualifiedName> ";"
<QualifiedName> ::= ID { "." ID }

<Definition>  ::= <DefFunc> | <DefStruct> | <DefEnum>
                | <DefModel> | <DefAgent> | <DefTask> | <DefHandler>
<Declaration> ::= <VarDecl> ";"
<DefFunc>     ::= "func" <TypeVoid> ID "(" [ <Params> ] ")" <Block>
<Params>      ::= <Param> { "," <Param> }
<Param>       ::= <Type> ID
<TypeVoid>    ::= <Type> | "void"
<Type>        ::= "int" | "double" | "bool" | "char" | "string" | ID
                | "list" "<" <Type> ">"
                | "map" "<" <Type> "," <Type> ">"
                | "future" "<" <TypeVoid> ">"
<DefStruct>   ::= "struct" ID "{" { <Field> } "}"
<Field>       ::= <Type> ID ";"
<DefEnum>     ::= "enum" ID "{" ID { "," ID } "}"
<VarDecl>     ::= <Type> ID [ "=" <Assign> ]
```

На верхнем уровне `func` начинает определение обычной функции, а тип без `func` начинает объявление переменной. Вызов функции записывается как `f(...)`. В теле блока `ID ID` означает объявление с именованным типом. Функция видна в собственном теле и может вызывать себя. Для запуска из командной строки нужна `func void main()`. Программа для оркестратора содержит обработчики `on` и может обходиться без `main`. Структуры состоят из полей. Перечисление используется через обращение к варианту, например `State.Ready`. Классы и методы исключены согласно SPEC. Общая память `board` отложена на следующую версию.

Контейнеры первой версии — динамический массив `list<T>` и словарь `map<K,V>`. Допустимые типы ключей — `int`, `bool`, `char`, `string` и перечисления. Индекс массива — `int`, с нуля. Пустой литерал словаря `map {}` получает тип из ожидаемого типа. Использование переменной без установленного значения проверяется семантически. Области видимости и проверка типов следуют SEM-1…SEM-5.

## 4. Инструкции (К-5, К-6)

```ebnf
<Block>       ::= "{" { <Stmt> } "}"
<Stmt>        ::= <Block> | <VarDecl> ";" | <Label> | <Expr> ";"
                | <If> | <While> | <DoWhile> | <For>
                | "return" [ <Expr> ] ";"
                | "break" ";" | "continue" ";" | "goto" ID ";"
                | <Context> | <Use> | <Hide> | <Attempt> | <Ensure>
<Label>       ::= ID ":" <Stmt>
<If>          ::= "if" "(" <Expr> ")" <Stmt> [ "else" <Stmt> ]
<While>       ::= "while" "(" <Expr> ")" <Stmt>
<DoWhile>     ::= "do" <Stmt> "while" "(" <Expr> ")" ";"
<For>         ::= "for" "(" [ <ForInit> ] ";" [ <Expr> ] ";" [ <Expr> ] ")" <Stmt>
<ForInit>     ::= <VarDecl> | <Expr>
```

В `<If>` необязательная часть обязательна к чтению, если после разбора первой ветки текущая лексема — `else`. Поэтому `else` относится к ближайшему незакрытому `if`, в том числе внутри тела цикла или помеченного оператора. Блок ограничивает область этого поиска. Это правило выбора — часть грамматики (G-6). У узла `If` всегда три позиции для потомков, третья пустая при отсутствии `else` (SYN-3).

Условие циклов и `if` имеет тип `bool`. Опущенное условие `for` считается истинным. Объявленная в заголовке переменная доступна в условии, шаге и теле этого цикла. `break` и `continue` привязаны к ближайшему циклу. `goto` ссылается на уникальную в пределах функции метку в своём или объемлющем блоке. Переход вперёд в том же блоке не перепрыгивает объявление переменной (SEM-6).

## 5. Выражения (К-3, К-4, G-5)

```ebnf
<Expr>        ::= <Assign> { "," <Assign> }
<Assign>      ::= <Or> [ "=" <Assign> ]
<Or>          ::= <And> { "||" <And> }
<And>         ::= <Equality> { "&&" <Equality> }
<Equality>    ::= <Compare> { ( "==" | "!=" ) <Compare> }
<Compare>     ::= <Add> { ( "<" | "<=" | ">" | ">=" ) <Add> }
<Add>         ::= <Mul> { ( "+" | "-" ) <Mul> }
<Mul>         ::= <Unary> { ( "*" | "/" | "%" ) <Unary> }
<Unary>       ::= ( "-" | "!" | "++" | "--" | "await" ) <Unary>
                | <Spawn> | <Postfix>
<Postfix>     ::= <Primary> { <Suffix> } [ "++" | "--" ]
<Suffix>      ::= "(" [ <Arguments> ] ")" | "[" <Expr> "]" | "." ID
<Arguments>   ::= <Assign> { "," <Assign> }
<Primary>     ::= INT | DOUBLE | CHAR | STRING | "true" | "false"
                | ID [ "{" [ <FieldValues> ] "}" ]
                | "(" <Expr> ")"
                | "map" "{" [ <MapEntries> ] "}"
                | <Ask> | <Prompt>
<FieldValues> ::= ID ":" <Assign> { "," ID ":" <Assign> }
<MapEntries>  ::= <Assign> ":" <Assign> { "," <Assign> ":" <Assign> }
```

| От низшего к высшему | Операции | Ассоциативность |
|---|---|---|
| 1 | запятая | слева |
| 2 | `=` | справа |
| 3–4 | `\|\|`, затем `&&` | слева на каждом уровне |
| 5–6 | `== !=`, затем `< <= > >=` | слева на каждом уровне |
| 7–8 | `+ -`, затем `* / %` | слева на каждом уровне |
| 9 | префиксные `- ! ++ --`, `await`, `spawn` | рекурсивно справа, у `spawn` собственная форма вызова |
| 10 | вызов, индекс, поле, постфиксные `++ --` | суффиксы применяются слева направо |

В исходном коде `[` и `]` образуют только суффикс индексации после выражения, например `values[0]` или `counts["ready"]`. В РБНФ квадратные скобки без кавычек по-прежнему обозначают необязательную часть правила.

Оператор-запятая вычисляет левый операнд, затем правый, даёт значение и тип правого. Запятая между аргументами, записями словаря и полями — разделитель, потому что их правила читают `<Assign>`. `f(a, b)` имеет два аргумента, а `f((a, b))` — один. Для присваивания левая часть должна быть доступной для записи переменной, полем или элементом контейнера. Результат имеет тип левой части. `++` и `--` требуют доступной для записи числовой цели, префикс возвращает новое значение, постфикс — прежнее. Логические операции принимают `bool`, `&&` и `||` сокращают вычисление. Допустимое неявное числовое преобразование — `int` в `double`. Сравнение даёт `bool`, поэтому `a < b < c` при числовых `a`, `b`, `c` отклоняется на этапе типов. `%` работает с `int`.

## 6. Агентная часть (А-1…А-9)

```ebnf
<DefModel>    ::= "model" ID "{" { <ModelProperty> } "}"
<ModelProperty> ::= ID ":" <Assign> ";"
<DefAgent>    ::= "agent" ID "{" { <AgentProperty> } "}"
<AgentProperty> ::= "model" ":" ID { "else" ID } ";"
                  | "tools" ":" "(" [ <Arguments> ] ")" ";"
                  | "budget" ":" UNIT { "," UNIT } ";"
                  | "space" ":" "worktree" ";"
                  | "system" ":" ( STRING | <Prompt> ) ";"
<DefTask>     ::= "task" <TypeVoid> ID "(" [ <Params> ] ")" <Block>
<DefHandler>  ::= "on" <QualifiedName> "(" [ <Params> ] ")" <Block>
<Context>     ::= "context" <Block>
<Use>         ::= "use" <Expr> ";"
<Hide>        ::= "hide" <Expr> ";"
<Attempt>     ::= "attempt" "(" <Expr> ")" <Block>
<Ensure>      ::= "ensure" <Assign> [ ":" <Assign> ] ";"
<Spawn>       ::= "spawn" ID "(" [ <Arguments> ] ")"
<Ask>         ::= "ask" "<" <Type> ">" "(" ID "," <Assign> ")"
<Prompt>      ::= PROMPT_FULL
                | PROMPT_HEAD <Expr> { PROMPT_MID <Expr> } PROMPT_TAIL
```

- **А-1, А-7, А-8.** Модель имеет строковый параметр `id`. Остальные допустимые параметры определяет адаптер. Агент объявляется с моделью, правами `tools` и бюджетом. `model: first else second;` задаёт порядок при разрешённом переходе к запасной модели. `space` по умолчанию `worktree`, `system` необязателен. Права на файлы, команды и сеть задаются библиотечными описателями в `tools`. Лимиты положительны, один на ресурс. `1ktok = 1000tok`, `1min = 60s`, после пересчёта лимит токенов должен быть целым. Семантика и исполнение проверяют права и бюджеты по SEM-8 и RUN-3.
- **А-2, А-3.** `ask<T>(Agent, prompt)` даёт значение явно заданного типа `T`. Из сериализуемого типа строится схема, ответ ей проверяется. Неверная структура ответа даёт ошибку. Второй аргумент принимает строку или промпт, в подстановках используется строковое представление значения.
- **А-4, А-5.** `use` и `hide` действуют внутри `context`. Вложенный блок наследует контекст, выход восстанавливает внешний. `attempt(n)` требует положительный `int`, включая первую попытку. Неуспешный `ensure` передаёт причину следующей попытке. Условия `ensure` — `bool`, причина при наличии — `string`. После исчерпания попыток проверка завершается ошибкой. Судья вызывается через тот же `ask<T>`.
- **А-6, А-9.** `spawn` принимает имя объявленной задачи, возвращает `future<T>`. `await` ждёт этот результат и возвращает `T`, либо сообщает ошибку задачи. Каждый запущенный `future` должен быть ожидаем по SEM-7. Сигнатуры обработчиков сверяются с зарегистрированными событиями, например `ci.failed`.

## 7. Ввод, вывод и разбор (К-8, G-4)

Ввод и вывод — обычные вызовы. `readInt()`, `readDouble()`, `readBool()`, `readChar()`, `readLine()` возвращают соответственно `int`, `double`, `bool`, `char`, `string`. Числа и `bool` читаются как отделённые пробелами значения, `readChar()` читает один символ, `readLine()` читает остаток строки без перевода строки. Неверное входное значение или конец ввода до значения — ошибка исполнения. `print(value)` пишет значение с переводом строки и возвращает `void`.

Для рекурсивного спуска у каждого нетерминала есть функция. На верхнем уровне токен `func` однозначно выбирает `<DefFunc>`. Остальные решения парсера приведены в таблице:

| Позиция | Как сделать выбор |
|---|---|
| Верхний уровень | `func` начинает определение функции. Тип начинает объявление переменной |
| Начало инструкции и начала `for` | `ID ID` — объявление, `ID :` в инструкции — метка, прочие начала с `ID` — выражение. `map <` — тип, `map {` — литерал |
| Первичное выражение после `ID` | `{` продолжает литерал структуры, иначе разбирается ссылка на имя |
| После тела `if` | `else` потребляется согласно правилу ближайшего `if` |
| Фрагменты промпта | Граница определяется начальным и конечным знаками лексемы `LiteralKind::Prompt` |

Уровни бинарных операций в фигурных скобках строятся циклом. Правое присваивание вызывает `<Assign>` рекурсивно после `=`. Последовательности верхнего уровня можно читать циклом. `EOF` проверяется ровно один раз, в конце. В AST запятая-операция даёт `Comma`, запятая в списке узла не даёт. `Assign` и `If` используют порядок потомков из API. Для узлов агентной части дополнение к таблице API составляет следующее отображение: `Ask` (тип ответа, имя агента, промпт), `Spawn` (имя задачи и аргументы), `Await` (операнд), `Attempt` (лимит и тело), `Ensure` (условие и необязательная причина), `Prompt` (текстовые части и выражения в порядке исходника). `Unit` — подвид `Literal`, отдельной категории `TokenType` для него нет.

## 8. Примеры для приёмки (G-7)

### Классическая программа

```vibe
struct Point { double x; double y; }
enum State { Ready, Done }

func int factorial(int n) {
    if (n <= 1) return 1;
    return n * factorial(n - 1);
}

func void main() {
    int a = readInt();
    int b = 3;
    double ratio = 2.5;
    bool ready = true;
    char separator = ':';
    string title = "Result";
    map<int, int> values = map { 0: 1, 1: 2, 2: 3 };
    map<string, int> counts = map { "ready": 1 };
    Point p = Point { x: 0.5, y: ratio };
    State s = State.Ready;
    if (a > b) a = a - b;
    else b = a;
    a = b = 3;
    for (int i = 0; i < 3; i++) {
        if (i == 1) continue;
        values[i] = factorial(i + 1);
    }
    while (a > 0) { a--; if (a == 1) break; }
    do { ++a; } while (a < 2);
    if (!ready) goto finish;
    print((counts["ready"], values[2]));
    print(p.x);
    finish: print(title);
}
```

### Агентная программа

Сигнатуры из модулей `fs`, `sh`, `ci`, `gh` в этом примере относятся к библиотеке исполнения. `Patch` — её тип результата с полем `diff: string`, `CiRun` — тип события с полями `step: string` и `log: string`. Модули и адаптеры нужны при исполнении программы.

```vibe
import fs;
import sh;
import ci;
import gh;

struct Verdict { bool ok; string reason; }
model fast { id: "small-model"; }
model strong { id: "large-model"; }

agent Fixer {
    model: fast else strong;
    tools: (fs.read("AGENTS.md"), fs.write("src/**"), sh.command("npm test"));
    budget: 2usd, 20min, 8ktok;
    space: worktree;
}
agent Judge {
    model: strong;
    tools: (fs.read("AGENTS.md"), fs.read("src/**"));
    budget: 1usd, 2min, 4ktok;
}

task Patch fix(CiRun run) {
    context {
        use fs.file("AGENTS.md");
        use run.log;
        attempt (3) {
            Patch patch = ask<Patch>(Fixer, `Исправь сбой на шаге ${run.step}.`);
            ensure sh.run("npm test").ok : "Тесты не прошли";
            context {
                hide run.log;
                Verdict result = ask<Verdict>(Judge, `Оцени патч ${patch.diff}.`);
                ensure result.ok : result.reason;
            }
            return patch;
        }
    }
}

on ci.failed(CiRun run) {
    future<Patch> pending = spawn fix(run);
    Patch patch = await pending;
    gh.open_pr(patch);
}
```

Два независимых вызова задач запускаются двумя последовательными `spawn` до первого `await`. Например, `future<int> first = spawn count("a"); future<int> second = spawn count("b"); print(await first + await second);` при объявленной задаче `task int count(string key) { return 1; }`.

### Контрольные фрагменты

Выражения и одиночные инструкции в таблице рассматриваются внутри функции, если не указано иначе.
