# Vibe: план разработки

План раскладывает шесть этапов курса на срок 2–3 месяца для команды из двух человек. Требования, на которые он ссылается, — в [SPEC.md](SPEC.md).

**Статус:** версия 0.1 от 10.11.2026. Даты — ориентиры: точных сроков приёмки нет, план сдвигается под них.

## 1. Принципы

- **Порядок этапов — как в курсе:** грамматика, лексический анализ, синтаксический анализ, семантический анализ, генерация, исполнение. Каждый этап сдаётся преподавателю отдельно.
- **Сначала обязательная часть.** На каждом этапе сперва делаются классические конструкции (К-1…К-8), затем агентные (А-1…А-9). Приёмка этапа не должна зависеть от агентной части.
- **Грамматика — источник истины.** Сначала меняется правило в грамматике, потом код анализаторов.
- **Методы заданы курсом:** форма Бэкуса–Наура, конечный автомат и бор в лексере, рекурсивный спуск в парсере.

## 3. Этапы

### Этап 0. Подготовка

- Каркас проекта: CMake, GoogleTest, пустые цели для транслятора и тестов.
- Сборка и тесты на Windows, Linux и macOS при каждом изменении (N-2).
- Ответы на открытые вопросы из раздела 7 [SPEC.md](SPEC.md), которые блокируют грамматику: контейнеры, ввод-вывод, `++` и `--`.

Готово, когда: проект собирается на трёх платформах и проходит один пробный тест.

### Этап 1. Грамматика

- Лексика: список лексем и правила их записи. **Нужна к 15.11**, чтобы начать лексер.
- Правила классической части по образцу с доски (G-3, G-5).
- Правила агентной части.
- Таблица приоритетов операций и примеры (G-5, G-7).

Результат: документы в `docs/grammar/`.

Готово, когда: выполнены G-1…G-7 и ответственный за анализаторы подтвердил, что по грамматике можно писать рекурсивный спуск.

### Этап 2. Лексический анализ

- Типы `Token`, `SourcePos`, `DiagnosticSink` из [API.md](API.md).
- Бор для ключевых слов (LEX-3).
- Автомат: идентификаторы, числа, символы, строки, операции, разделители, комментарии (LEX-2, LEX-6).
- Лексические ошибки (LEX-8).
- Промпт-литерал с подстановками (LEX-10) — после классической части.
- Программа, печатающая список лексем.

Результат: код лексера, тесты, описание автомата и коды ошибок в `docs/analysis/`.

Готово, когда: выполнены LEX-1…LEX-10 и проходят тесты, включая примеры с доски: `a+++b`, `a = if : b`, `if (a > #b)`, `3.5.7`.

### Этап 3. Синтаксический анализ

- Тип `Node` и виды узлов из [API.md](API.md).
- Выражения: уровни приоритета, левая ассоциативность циклом, присваивание рекурсией (SYN-3).
- Операторы: ветвление, циклы, переходы, блоки.
- Определения: функции с ключевым словом `func` (К-7), структуры, перечисления.
- Агентные конструкции.
- Синтаксические ошибки (SYN-5) и печать дерева (SYN-8).

Результат: код парсера, тесты, соответствие «правило грамматики — функция» в `docs/analysis/`.

Готово, когда: выполнены SYN-1…SYN-8, каждый пример из грамматики (G-7) разбирается или отклоняется как ожидается, а `if (a > b) a = a - b;` даёт дерево с доски.

### Этап 4. Семантический анализ

- Таблицы имён и области видимости (SEM-1).
- Типы выражений и проверки операций (SEM-2…SEM-5).
- Переходы, включая ограничения `goto` (SEM-6).
- Агентные проверки (SEM-7), затем бюджеты и права (SEM-8).

Результат: код анализатора, тесты, список проверок с кодами ошибок в `docs/analysis/`.

Готово, когда: выполнены SEM-1…SEM-10 и на каждую проверку есть пример программы, которую анализатор отклоняет.

### Этап 5. Генерация

- Перевод классических конструкций в C++ (GEN-2).
- Перевод агентных конструкций в вызовы библиотеки времени исполнения.
- Команда, которая транслирует файл и собирает результат.

Готово, когда: программы-примеры классической части транслируются, собираются и дают ожидаемый вывод (GEN-3).

Подробности — в `docs/generation/`, пишутся к началу этапа.

### Этап 6. Исполнение

Порядок, в котором появляются части библиотеки:

1. Вызов модели и разбор ответа по схеме (А-1, А-2).
2. Агентный цикл с инструментами: чтение и запись файлов, запуск команд.
3. Контекст, повтор с проверками (А-4, А-5).
4. Бюджеты и права в одной точке проверки (А-7, RUN-3).
5. Параллельные задачи и изоляция в рабочих каталогах git (А-6, А-8).
6. Оркестратор с обработчиками событий (А-9).
7. Стыковка со сгенерированным кодом и сценарий из [PRD.md](PRD.md).

Готово, когда: сценарий из PRD проходит целиком на тестовом репозитории.

Подробности — в `docs/execution/`, пишутся по ходу этапа.

## 4. Риски для срока

- **У этапов 5 и 6 нет ответственного.** Этап 6 — самая большая часть работы. Решение нужно к концу этапа 1 (22.11), иначе параллельный старт библиотеки сорвётся.
- **Грамматика меняется после начала анализаторов.** Каждое изменение правила — это правка парсера и тестов. Агентную часть грамматики стоит заморозить к началу этапа 3 (30.11).
- **Сроки приёмки неизвестны.** Если преподаватель назначит сдачу раньше ориентира, агентная часть этапа переносится на после сдачи.
- **Праздники 01.01 – 08.01** попадают на этап 5; в графике на него заложено три недели вместо двух.
- **Три платформы.** Без автоматической сборки на всех трёх расхождения найдутся поздно; поэтому она в этапе 0.

## 5. Что сокращать при нехватке времени

По порядку, от первого к последнему:

1. Обработчики событий и долгоживущий оркестратор (А-9): сценарий запускается как программа с точкой входа `func void main()`.
2. Статическая проверка бюджетов (третий пункт SEM-8): остаётся только проверка при исполнении.
3. Параллельные задачи (А-6): задачи выполняются последовательно.

Классическая часть языка и все шесть этапов не сокращаются.
