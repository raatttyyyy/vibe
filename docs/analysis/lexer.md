# Лексический анализатор

Лексер — этап 2 курса. Он превращает текст программы в последовательность лексем по разделу 2 [грамматики](../grammar/Vibe_grammar.md) и выполняет требования LEX-1…LEX-10 из [SPEC](../SPEC.md). Типы на входе и выходе — из [API](../API.md).

## 1. Где что лежит

| Файл | Что в нём |
|---|---|
| `src/common/source.h` | `SourcePos`, `SourceRange` |
| `src/common/diagnostics.h` | `Diagnostic`, `DiagnosticSink`, `formatDiagnostic` (N-6) |
| `src/lexer/token.h` | `Token`, `TokenType`, `LiteralKind` |
| `src/lexer/keyword_trie.h` | Бор ключевых слов (LEX-3) |
| `src/lexer/lexer.h` | `tokenize(source, diags)` |
| `src/lexer/lexer.cpp` | Автомат |
| `src/tools/vibe_lex.cpp` | Программа `vibe-lex` для сдачи этапа |
| `tests/lexer/` | Тесты GoogleTest; номер требования указан в комментарии к тесту |
| `tests/data/` | Примеры для `vibe-lex`: обе программы из раздела 8 грамматики и файл с ошибками |

## 2. Запуск

```
cmake -S . -B build
cmake --build build
ctest --test-dir build --output-on-failure
build/src/vibe-lex tests/data/classic.vibe
```

`vibe-lex` печатает по строке на лексему: позицию начала, тип (у литерала — с видом) и исходный текст. Переводы строк и табуляции внутри лексемы печатаются как `\n`, `\r`, `\t`. Сообщения об ошибках идут в поток ошибок. Код возврата: 0 — ошибок нет, 1 — есть лексические ошибки, 2 — не указан или не открылся файл.

```
1:1       Keyword          if
1:4       Delimiter        (
1:5       Identifier       a
1:7       Operator         >
1:9       Unknown          #
...
tests/data/lexical_errors.vibe:1:9: ошибка LEX001: недопустимый символ '#'
```

Сообщения выводятся в UTF-8. В консоли Windows с другой кодовой страницей русский текст может отображаться неверно; помогает `chcp 65001`.

## 3. Автомат

Лексер написан вручную как конечный автомат, закодированный переходами в коде (LEX-2). Регулярные выражения и генераторы не используются (N-3).

Главный цикл: пропустить пробелы и комментарии, затем из начального состояния выбрать ветку по первому символу. Позиция в тексте только растёт, а заглядывание вперёд не больше двух символов, поэтому время линейно от длины входа. Рекурсии нет: вложенные подстановки в промптах хранятся в явном стеке.

### 3.1. Начальное состояние

| Первый символ | Ветка |
|---|---|
| пробел, `\t`, `\r`, `\n` | пропуск (LEX-9) |
| `//` | комментарий до конца строки |
| `/*` | комментарий до `*/`, не вложенный |
| `A…Z a…z _` | идентификатор или ключевое слово |
| `0…9` | число |
| `'` | символ |
| `"` | строка |
| `` ` `` | промпт |
| `( ) [ ] ; : .` | разделитель |
| `{` `}` | разделитель; внутри подстановки ещё и счётчик скобок (п. 3.6) |
| `* / % ,` | операция из одного символа |
| `+ - = ! < >` | операция; следующий `+`, `-` или `=` дополняет её до двухсимвольной |
| `&` `\|` | операция `&&` или `\|\|`; одиночный символ — ошибка LEX002 |
| остальное | недопустимые символы, LEX001 |

Двухсимвольная операция выбирается всегда, когда её второй символ следует сразу (LEX-6): `a+++b` даёт `a`, `++`, `+`, `b`. Операции `>>` нет, поэтому `list<list<int>>` закрывается двумя `>`.

### 3.2. Идентификаторы и ключевые слова

Пока читаются символы `[A-Za-z0-9_]`, автомат одновременно переходит по бору ключевых слов (LEX-3). Если после последнего символа состояние бора помечено как конец слова, лексема — `Keyword`, иначе `Identifier`. Выпав из бора, автомат остаётся в мёртвом состоянии до конца идентификатора, поэтому `funcName` и `iff` — идентификаторы. Бор строится один раз из списка ключевых слов грамматики.

### 3.3. Числа

В `scanNumber()` переходы автомата записаны в порядке частей числа. Каждая часть читается один раз.

| Часть | Что читает лексер |
|---|---|
| Целая часть | Все начальные цифры. Вид литерала — `Int`. |
| Дробная часть | Если после точки идёт цифра, прочитать точку и цифры, установить вид `Double`. Ещё одна точка с цифрой даёт LEX003. |
| Экспонента | После `e` или `E` прочитать необязательный знак и хотя бы одну цифру, установить вид `Double`. Отсутствие цифр или точка с цифрой после порядка дают LEX003. |
| Суффикс | Если следующая буква или `_` начинает суффикс, прочитать его целиком по правилу идентификатора. Суффиксы `usd`, `tok`, `ktok`, `s` и `min` дают вид `Unit`. Неизвестный суффикс или точка с цифрой после единицы дают LEX003. |

При ошибке `malformedNumber()` дочитывает символы идентификатора и точки, за которыми идёт цифра. Вся запись становится одной лексемой `Unknown`, а сообщение указывает первую причину ошибки.

Точка без следующей цифры в число не входит и остаётся разделителем: `3.x` — это `3`, `.`, `x`. Знак перед числом — отдельная операция. Ошибочный фрагмент дочитывается целиком, поэтому `3.5.7` и `35k6` дают по одной лексеме `Unknown`.

### 3.4. Символы и строки

`'…'` и `"…"` читаются одинаково. Допустимые escape-последовательности — `\n`, `\r`, `\t`, `\\` и своя кавычка: `\'` в символе, `\"` в строке. Физический перевод строки или конец файла до закрывающей кавычки означает незакрытый литерал; лексема `Unknown` заканчивается перед переводом строки, и следующая строка разбирается заново. Символ после декодирования — ровно один символ Unicode, строка может быть пустой.

Если в одном литерале несколько ошибок, сообщается одна, самая важная: незакрытый литерал, затем неверная escape-последовательность, затем длина символа.

### 3.5. Комментарии

`//` пропускает текст до перевода строки или конца файла. `/*` пропускает текст до первого `*/`: комментарии не вкладываются, и в `/* /* */ */` хвост `*/` — это операции `*` и `/`. Незакрытый `/*` даёт лексему `Unknown` от `/*` до конца файла.

### 3.6. Промпты (LEX-10)

Промпт делится на текстовые части и лексемы выражений внутри `${ … }`. Все текстовые части — `Literal` вида `Prompt`, роль видна по границам `lexeme`:

| Часть | Начинается | Заканчивается |
|---|---|---|
| `PROMPT_FULL` | `` ` `` | `` ` `` |
| `PROMPT_HEAD` | `` ` `` | `${` |
| `PROMPT_MID` | `}` | `${` |
| `PROMPT_TAIL` | `}` | `` ` `` |

`` `a ${x} b` `` даёт `` `a ${ ``, `x`, `` } b` ``.

После `${` лексер кладёт в стек запись о подстановке со счётчиком фигурных скобок, равным нулю, и читает обычные лексемы. `{` внутри подстановки увеличивает счётчик верхней записи, `}` при ненулевом счётчике уменьшает его; обе остаются разделителями. `}` при нулевом счётчике снимает запись со стека и начинает текстовую часть `PROMPT_MID` или `PROMPT_TAIL`. Обратная кавычка внутри подстановки начинает вложенный промпт со своей записью в стеке. Строки и комментарии внутри подстановки читаются как обычно, поэтому `}` в них подстановку не закрывает. Вне промптов стек пуст, и `{`, `}` — просто разделители.

В тексте промпта экранируются только `` \` ``, `\\` и `\${`; `$` и `{` по отдельности — обычный текст. Переводы строк в тексте разрешены, поэтому `\n` в промпте не нужен и считается ошибкой LEX007.

Если файл кончился внутри текста промпта, текстовая часть становится `Unknown` (LEX009). Если файл кончился внутри подстановки, `Unknown` становится открывшая её часть `PROMPT_HEAD` или `PROMPT_MID` (LEX010); сообщение указывает на её `${`.

### 3.7. Позиции (LEX-5)

Строка и столбец считаются с единицы, столбец — в символах Unicode, а не в байтах; табуляция — один символ. Смещение — в байтах с нуля. Перевод строки — `\n`, `\r\n` или одиночный `\r`. Испорченный байт UTF-8 вне литералов считается одним символом и даёт LEX001; внутри строк, символов, промптов и комментариев текст не проверяется (L-4). `range.end` указывает на позицию сразу за лексемой. У `EndOfFile` начало и конец совпадают с концом текста.

## 4. Ошибки (LEX-8)

Ошибочный фрагмент становится лексемой `Unknown` с точным исходным текстом. На каждую такую лексему в `DiagnosticSink` приходит сообщение с этапом `Lexer`, уровнем `Error`, кодом и диапазоном лексемы. После ошибки анализ продолжается до конца файла, и последовательность всё равно заканчивается `EndOfFile`.

| Код | Ошибка | Пример | Текст сообщения |
|---|---|---|---|
| LEX001 | Недопустимый символ; подряд идущие недопустимые символы — одна лексема | `#`, `@#$`, `имя` | `недопустимый символ '#'` |
| LEX002 | Одиночные `&` или `\|` | `a & b` | `неполная операция '&': ожидалось '&&'` |
| LEX003 | Неверно записанное число | `3.5.7`, `35k6`, `12e`, `1e5.3`, `2usdx` | `неверно записанное число '3.5.7': после дробной части ожидался конец числа, встретилась вторая точка` |
| LEX004 | Незакрытая строка | `"abc` | `незакрытая строка: ожидалась закрывающая ", встретился перевод строки` |
| LEX005 | Незакрытый символ | `'a` | `незакрытый символьный литерал: ожидалась закрывающая ', встретился конец файла` |
| LEX006 | В символе не один символ | `''`, `'ab'` | `символьный литерал: ожидался ровно один символ, встретилось символов: 2` |
| LEX007 | Недопустимая escape-последовательность в строке, символе или промпте | `"\q"`, `'\"'`, `` `\n` `` | `недопустимая escape-последовательность '\q': ожидалось \n, \r, \t, \\ или \"` |
| LEX008 | Незакрытый комментарий | `/* …` | `незакрытый комментарий: ожидалось '*/', встретился конец файла` |
| LEX009 | Незакрытый промпт | `` `abc `` | ``незакрытый промпт: ожидалась закрывающая `, встретился конец файла`` |
| LEX010 | Незакрытая подстановка в промпте | `` `a ${x `` | `незакрытая подстановка в промпте: ожидалась '}', встретился конец файла` |

Управляющие символы и испорченный UTF-8 в тексте сообщений записываются как `\xNN`.

## 5. Решения, которых нет в грамматике

Грамматика не описывает эти случаи явно; лексер поступает так, и тесты это закрепляют. Если ответственный за грамматику решит иначе, меняются код и этот раздел.

- Одиночный `\r` — перевод строки, как и `\r\n`.
- Метка порядка байтов UTF-8 в начале файла не пропускается и даёт LEX001.
- Подряд идущие недопустимые символы объединяются в одну лексему `Unknown`, чтобы слово на кириллице давало одно сообщение, а не по одному на букву.
- В символе `\"`, а в строке `\'` — недопустимые escape-последовательности: грамматика разрешает экранировать только свою кавычку.
- Единица измерения различает регистр: `2Usd` — ошибка LEX003. `2 usd` — число и идентификатор.
