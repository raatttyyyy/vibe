# Инструкции для ИИ-агентов

Этот файл читают ИИ-агенты, которые пишут код и документацию в репозитории Vibe.

Vibe — язык программирования для управления разработкой силами ИИ-агентов и одновременно учебный проект: транслятор проходит шесть этапов курса, и каждый этап принимает преподаватель. Транслятор пишется на C++20 и переводит программу на Vibe в код на C++.

## Жёсткие правила

Они следуют из требований курса; нарушение означает несданный этап.

1. **Лексер пишется вручную** как конечный автомат, работает за линейное время. Ключевые слова ищутся бором. Не используй `std::regex`, flex, re2c и подобное.
2. **Парсер пишется вручную** рекурсивным спуском: одна функция на нетерминал грамматики, имя функции соответствует имени нетерминала. Не используй ANTLR, Bison и другие генераторы.
3. **Грамматика — источник истины.** Парсер повторяет грамматику из `docs/grammar/`. Если код и грамматика расходятся, сначала исправляется грамматика (её ответственным), потом код.
4. **Этапы не смешиваются.** Лексер не проверяет синтаксис, парсер не проверяет имена и типы, семантика не генерирует код. Модули общаются только через типы из [API.md](API.md).
5. **Типы лексем** — `keyword`, `operator`, `literal`, `id`, `delimiter`, `unknown` и служебный конец файла. Не добавляй новые без изменения SPEC и API.
6. **Сначала классическая часть.** В каждом модуле сперва реализуются требования `К-1…К-8`, затем агентные конструкции.
7. **Анализаторы зависят только от стандартной библиотеки C++.** GoogleTest — только в тестах. Новая зависимость где угодно — только по согласованию с человеком.

## Сборка и тесты

Инструменты: C++20, CMake, GoogleTest. Код должен собираться и проходить тесты на Windows, Linux и macOS.

Команды после появления `CMakeLists.txt`:

```
cmake -S . -B build
cmake --build build
ctest --test-dir build --output-on-failure
```

Перед тем как сообщить, что задача сделана, собери проект и запусти тесты. Если не удалось, скажи об этом прямо и приведи вывод.

## Код

- Всё лежит в пространстве имён `vibe`.
- Имена в коде — на английском.
- Не используй возможности, привязанные к одной платформе или одному компилятору.
- Узлами дерева владеет `std::unique_ptr`; `new` и `delete` напрямую не пишутся.
- Об ошибках во входной программе сообщай через `DiagnosticSink` с позицией и кодом, а не исключением и не печатью в поток.
- Текст сообщения об ошибке говорит, что ожидалось и что встретилось.

## Тесты

- На каждое требование из SPEC, которое реализуешь, нужен тест; в названии или комментарии теста укажи номер требования.
- На каждую проверку нужны и правильный пример, и неправильный.
- Примеры с доски обязательны: `a+++b`, `a = if : b`, `if (a > #b)`, `3.5.7`, дерево для `if (a > b) a = a - b;`, дерево для `5 + 3 + 7`.
- Не меняй ожидаемый результат теста, чтобы тест прошёл. Если ожидание неверно, объясни почему.
